# Сантех Майстер — лендінг

Односторінковий сайт сантехнічної служби «Сантех Майстер», зверстаний за макетом із Figma.
Стек: **Vite + React** (JavaScript), без зайвих залежностей.

## Запуск

```bash
npm install      # встановити залежності
npm run dev      # запуск dev-сервера (http://localhost:5173)
npm run build    # production-збірка у dist/
npm run preview  # локальний перегляд production-збірки
```

## Структура

```
src/
├── components/        # компоненти секцій + спільні (Modal, ConsultForm, Icons)
├── data/              # увесь текстовий контент і дані
│   ├── site.js        #   бренд, телефон, email, меню
│   ├── services.js    #   картки послуг + промо-блок
│   ├── pricing.js     #   прайс-лист
│   ├── about.js       #   секція «Про мене»
│   └── works.js       #   кейси «Наші роботи» (з даними для модалок)
├── styles/global.css  # глобальні стилі + CSS-змінні (кольори, радіуси, відступи)
├── App.jsx            # збірка сторінки + керування модалками
└── main.jsx
public/images/         # зображення (витягнуті з Figma-файлу)
```

## Секції

Хедер (sticky) · Hero · Послуги · Ціни · Про мене · Наші роботи (карусель) · Контакти · Футер.
Модальні вікна: «Викликати майстра» (форма) і «Деталі роботи» (з каруселі).

## Як змінювати контент

- **Тексти, ціни, послуги, кейси** — редагуються у файлах `src/data/*.js`, без правок розмітки.
- **Кольори / відступи / радіуси** — CSS-змінні у верхній частині `src/styles/global.css`.
- **Зображення** — лежать у `public/images/`; шляхи вказані в `src/data/*.js`. Достатньо замінити файл або шлях.
  Кожне зображення має `.webp`-версію (підвантажується автоматично) + оригінал як fallback через компонент [`Picture`](src/components/Picture.jsx). Замінюючи фото, бажано покласти і `.jpg/.png`, і `.webp` з тим самим іменем.

## Форми та заявки в Telegram

Форми (валідація, маска номера) відправляють заявку на Netlify Function
[`netlify/functions/lead.js`](netlify/functions/lead.js), а та пересилає її майстру в Telegram.
Клієнту показується «Дякуємо», при помилці мережі — повідомлення з пропозицією повторити.
Від ботів захищає приховане поле-пастка (`website`).

### Налаштування (один раз)

1. **Бот.** У Telegram відкрийте `@BotFather` → `/newbot` → вигадайте ім'я та username (на `bot` закінчується). Збережіть токен.
2. **Chat ID.** Відкрийте свого бота й натисніть Start. Потім напишіть `@userinfobot` — він покаже ваш `Id`.
   Для кількох отримувачів (майстер + диспетчер) — кожен має написати боту `/start`; ID вказуються через кому.
3. **Netlify → Site configuration → Environment variables:** додайте `TELEGRAM_BOT_TOKEN` і `TELEGRAM_CHAT_ID`.
4. **Redeploy** сайту (Deploys → Trigger deploy), щоб змінні підхопились.
5. Надішліть тестову заявку з сайту — повідомлення має прийти в Telegram.

> Деплой функцій працює через GitHub або Netlify CLI. Перетягування папки `dist` функції **не** розгортає.

Локальна перевірка: `npm i -g netlify-cli`, скопіюйте `.env.example` у `.env`, заповніть, запустіть `netlify dev`.
(Звичайний `npm run dev` функцій не запускає — заявка просто логується в консоль.)

Кожна заявка тегується, щоб майстер одразу бачив контекст:

| Поле | Значення |
|------|----------|
| `type` | `consult` (консультація) або `callout` (технічний виклик) |
| `source` | звідки заявка: `hero` / `contacts` / `call-modal` |
| `service` | назва послуги/роботи, якщо клієнт прийшов із картки (інакше `null`) |
| `problem` | опис проблеми (тільки для техвиклику; необов'язкове поле) |

**Логіка двох намірів:** «Консультація» — легка форма (ім'я + телефон), «Технічний виклик» — додає поле опису проблеми. Кнопки в хедері/футері та «Замовити послугу» в кейсах ведуть на техвиклик; «Детальніше» на послугах і кнопки «Консультація» — на консультацію з підставленою назвою послуги.

## Контактні дані

Телефон, email, Viber, Telegram — у `src/data/site.js`.

- **Телефон:** на смартфоні відкривається набір номера; на комп'ютері номер копіюється і з'являється підказка.
- **Viber:** `viber://chat?number=…` (на ПК використовується варіант без `+`). Номер має бути зареєстрований у Viber.
- **Telegram:** впишіть свій username у `telegramUsername` (початок `site.js`). Поки порожньо — кнопки Telegram приховані.

## Аналітика

Події штовхаються у `window.dataLayer` (Google Tag Manager) і в `gtag` (GA4), якщо підключено —
через [`src/lib/analytics.js`](src/lib/analytics.js). Поки тег не вставлено в `index.html`,
події просто логуються в dev-консоль. Що відстежується:

| Подія | Коли |
|-------|------|
| `open_form` | відкриття форми (`form_type`: consult / callout, + `service`) |
| `lead_submit` | успішна відправка заявки (`form_type`, `source`, `service`, `has_problem`) |
| `open_work` | відкриття деталей кейсу (`work_id`) |
| `contact_click` | клік по телефону/email/Viber/Telegram (`channel`, `placement`) |

Щоб увімкнути збір — додати GTM або GA4 snippet у `index.html`; код подій уже на місці.
